# Contract: Test Vault Structure & Verification Baseline

**Feature**: `002-e2e-test-env` (consolidated with `003-manual-test-workflow`) | **Date**: 2026-10-27

Defines the committed layout of `test-vault/` and the fixed board structure that serves as the verification baseline (SC-002-004, Assumption "Known verification baseline").

## Directory layout

```text
test-vault/
├── Board.md
├── S1.md
├── S2.md
├── S3.md
├── S4.md
├── S5.md
├── S6.md
└── .obsidian/
    ├── community-plugins.json
    └── plugins/
        └── obsidian-usm-plugin/
            ├── manifest.json     # committed (copied from repo root by e2e:setup)
            ├── styles.css        # committed (copied from repo root by e2e:setup)
            └── main.js           # gitignored (built by e2e:setup)
```

## Committed vs generated

| Path | Committed | Notes |
|------|-----------|-------|
| `Board.md`, `S1.md`–`S6.md` | yes | Fixture content; the verification baseline. |
| `.obsidian/community-plugins.json` | yes | Enables the plugin. |
| `.obsidian/plugins/obsidian-usm-plugin/manifest.json`, `styles.css` | yes | Source artifacts copied by `e2e:setup`. |
| `.obsidian/plugins/obsidian-usm-plugin/main.js` | **no** (gitignored) | Build artifact; regenerated by `e2e:setup`. |
| `.obsidian/app.json`, `appearance.json`, `core-plugins.json`, `workspace.json` | **no** (gitignored) | Obsidian runtime/working files; created when the vault is opened. |

## Board file (`Board.md`)

Conforms to `specs/001-user-story-map/contracts/board-file-format.md`. Frontmatter: `usm-board: true`, `usm-release-order: appearance`. Body: an ordered wikilink list referencing `S1`–`S6`, one duplicate of `S1` (alias), and one broken link (`[[Missing story]]`).

## Verification baseline (expected rendered structure)

Derived from the fixture set above using the plugin's grouping rules (first-appearance column order, case-insensitive value matching, Unassigned fallback):

| Metric | Expected value | DOM selector counted |
|--------|----------------|----------------------|
| Task columns | **4** | `.usm-board-header .usm-header-cell--task` |
| Activity columns | **3** | `.usm-board-header .usm-header-cell--activity` |
| Release rows | **3** | `section.usm-release` |
| Story cards | **8** | `.usm-story-card` (7 notes + 1 broken-link placeholder) |

Task column breakdown (Activity → Task):
1. Onboarding → First run (S1, S2, S6)
2. Unassigned → Unassigned (S3)
3. Logowanie → Login (S4)
4. Unassigned → First run (S5)

Release rows (rendered order): `Unassigned` (auto-generated, always rendered first), then the assigned releases in appearance order: `1.0 MVP`, `2.0`.

## Invariants

- **Reproducibility (FR-002-004)**: a fresh clone + `npm run e2e:setup` yields this exact structure.
- **Isolation (SC-002-002)**: nothing outside `test-vault/` is read or modified during a run.
- **Baseline stability**: changing any fixture file changes the baseline and MUST update this contract in the same change.
